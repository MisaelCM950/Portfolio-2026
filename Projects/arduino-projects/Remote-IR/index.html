1. Interactive Tool Deck

  • 1.What does the tool do?

    A hardware-controlled web dashboard that allows a user to interact with their computer screen entirely via a physical infrared (IR) Arduino remote control. The system features two core applications: a fully operational grid-navigated Calculator and a Media Deck that controls desktop Spotify in real time.

  • 2. Why I built it:

    I built this platform to bridge the gap between physical hardware components and modern web software. While I wanted to deepen my understanding of microcontrollers like the Arduino UNO and components like IR Receivers, my primary goal was learning how to establish a low-latency communication pipeline between local hardware and a browser-based user interface.

  • 3. How it works:

    • The system boots up into a selection menu. The user navigates the desktop layout using the remote’s directional arrow keys.
    • For the user:
      The Calculator: The user navigates smoothly through a responsive button grid. Pressing “OK” keys in inputs, triggering navigation sound effects, and computing complex text equations.

      The Music Deck: It offers a split screen-layout. The web dashboard acts as a dedicated hardware deck while desktop Spotify snaps to the other half of the monitor. Users can visually cycle through custom UI panels to track-skip, play, pause, or alter the volume.
    • Technical:
      1. Hardware Layer: An IR receiver module captures physical infrared light waves, converts them to Hexadecimal code strings “0xB54AFF00”, and streams them over a USB serial connection “COM6” at a “9600” baud rate using the Arduino IDE.
      2. Backend Server: Built with Node.js and Express. It utilizes “@serialport/parser-readline” to cleanly capture incoming data streams, host the server locally on port “3000”, and handle asynchronous system tasks.
      3. Communicatoin Layer (Socket.io): Establishes an active WebSocket link to instantly push remote strings("UP", "RI", "BA", "1") from the server straight into the browser window with zero noticeable lag.

  • 4. Technical Challenges:

    1. Infinite Circular Grid Navigation:
      The Struggle: Preventing navigation arrays from throwing errors or breaking layout flow when moving past boundaries

      The Solution: Implementing cyclic array indexing mathematics. By applying the modulus remainder calculation, the cursor smoothly wraps around screen boundaries indefinitely. 
      if (cmd === 'RI') { // If index reaches the array length,
the remainder snaps it back to 0 currentIndex = (currentIndex + 1) %
items.length; } else if (cmd === 'LE') { // Adding items.length keeps the
integer positive when moving backward past 0 currentIndex = (currentIndex - 1 +
items.length) % items.length; }
    2. Native OS Key Interception & Library Deprecation:
      The Struggle: Standard Node.js automated keyboard libraries require intensive native system dependencies (Python, C++ compliers) that cause major build crashes on standard Windows setups.

      The Solution: Bypassing external libraries completely by running native, asynchronous Windows PowerShell sub-processes via Node’s “child—process” execution layer.

natively to Windows OS if (action === 'PLAY') { // Char 179 tells the system
hardware kernel to trigger a global Play/Pause event exec(`powershell -c
"(New-Object -ComObject WScript.Shell).SendKeys([char]179)"`); }

  • 5. What I learned:

    Through this project, I mastered the fundamentals of Event-Driven Architecture and Full-Stack JavaScript integration. I learned how to establish robust Serial Port pipelines between microcontrollers and backend engines, manipulate the web DOM dynamically based on hardware events, and utilize system shells to bridge separate desktop software ecosystems together under one remote control
