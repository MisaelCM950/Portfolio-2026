6. EstudIAmigo

🗓️ June 12th – June 14th 2026

  • What does the tool do?

    EstudIAmigo is an interactive, AI-driven mathematics learning platform that transforms static study materials (such as uploaded PDFs) into dynamic, personalized roadmaps. Designed around active recall principles, the platform integrates the Feynman Technique as a core mechanic: to advance through levels, users cannot simply select an answer; they must explain the underlying logic of their solution in their own words. The platform evaluates their conceptual understanding, guides them through errors with targeted questioning, and dynamically generates custom vector geometry images using inline SVG rendering to keep study sessions interactive and visually engaging.

  • Why I built it?

    I built EstudIAmigo during my first hackathon, Innovathon 2026, hosted by the Universidad Tecnológica de Chihuahua (UTCH). Having spent months self-studying for the SAT to apply to universities, I experienced firsthand how isolating, dry, and passive traditional learning resources can be. I wanted to design an educational platform that shifts the learning paradigm from memorization to active teaching.

    Collaborating in a team of four, I took the lead in architecting the core platform. The project was an intense sprint to push my technical limits: building a complete platform under a strict 48-hour limit, mastering AI agent prompting, and parsing raw PDF documents into structured roadmaps.

  • How it works:

    • For the user:
      • Dynamic roadmaps: The user uploads a study document (e.g., a PDF textbook on fractions and geometry). The system extracts the text, analyzes the topics, and generates a structured 6-level learning path going from basic concepts to advanced applications.
      • The Feynman Active Learning Loop: In each level, the AI presents a math problem. When the user provides an answer, the interface prompts them to explain their reasoning. The user must articulate their mathematical process to proceed, transforming passive reading into active teaching.
      • Socratic Dialogue Guidance: If the user’s explanation is mathematically incomplete or incorrect, the AI acts as a Socratic tutor—asking guiding questions rather than simply revealing the final answer.
      • Dynamic Visual Geometry: For geometry modules, the application renders interactive vector images directly in the chat window, providing visual context for problems that need it.
      • Free-Form Socratic Chat: Students can initiate open study sessions without uploading a document, utilizing image uploads to get step-by-step explanations of photographed equations.

  • Technical Architecture & Orchestration:

    The application is built using a client-server architecture designed for high-throughput text and image processing:

    • Next.js & React (Typescript): Powers the front-end dashboard, featuring a custom, animated zig-zag learning path, dynamic LaTeX mathematical rendering via KaTex and Markdown, and responsive layouts styled with TailwindCSS.
    • Node.js & Express Backend: Manages file ingestion payloads, coordinates PDF parsing pipelines, and structures prompts for LLM execution.
    • OpenAI GPT-4o-mini API: Serves as the cognitive tutor. It evaluates user inputs, maintains the state of the Socratic dialogue, and generates structured JSON roadmaps.
    • Pdf2json Library: Extracts raw text content from base64-encoded PDF payloads transmitted from the client, feeding clean textual summaries into the LLM context.

  • Technical challenges:

    1. Level Progression State Synchronization & Clean History Reset:
      The problem: In a structured learning path, the system must synchronize the backend’s evaluation of the user’s progress with the frontend’s visual roadmap. A major issue arose during level transitions: if the entire chat history from the previous level was sent in subsequent API requests, the LLM became highly prone to context leakage—combining past math problems with new topics, breaking its internal state machine, and failing to raise the difficulty of the next level.
      The solution: I designed a token-based handshake protocol between the client and the server. When the backend determines that the user has successfully explained the concept, it attaches a hidden token [TEMA_APROBADO] to its response and updates the roadmap nodes. The frontend intercepts this response, strips the token from the visible message, and renders a Next Level call-to-action button. When clicked, the client updates the local learning path state, clears the message array, and initiates a clean API call with an empty history array (history: []) and the new topic. This keeps the LLM’s context window focused and error-free.

    2. Structuring and PDF extraction:
      The problem: Generating a structured roadmap requires parsing raw text from a PDF, extracting core mathematical concepts, and forcing the LLM to return a strict JSON schema containing exactly 6 levels alternating between Fractions and Geometry. However, LLMs are inherently conversational and frequently wrap JSON outputs in Markdown code blocks (e.g., ```json…```) or attach introductory text, causing native JSON.parse operations to throw critical syntax errors and crash the application.
      The solution: I implemented cleanJsonOutput. Instead of relying solely on system prompts to enforce formatting, this function scans the raw string return, locates the first opening curly brace `{` and the final closing curly brace `}`, and extracts the precise substring between them. This approach ensures that even if the LLM surrounds the JSON with conversational text or markdown blocks, the application isolates and parses properly. 
      function cleanJsonOutput(content) {
  const start = content.indexOf('{');
  const end = content.lastIndexOf('}');
  if (start === -1 || end === -1) return null;
  try {
    return JSON.parse(content.slice(start, end + 1));
  } catch {
    return null;
  }
}
