1.Calculator

  • 1.What does the tool do?

    • The Cyber-Nutrient Calculator is a sci-fi themed web application that calculates a user’s Total Daily Energy Expenditure (TDEE). It provides precise, dynamically generated macronutrient breakdown (proteins, fat, carbohyrdates) tailored to specific physical goals: weight loss, maintenance, or weight gain.

  • 2. Why I built it:

    • I built this to escape “Tutorial Hell” and force myself to understand front-end architecture (HTML layouts, CSS styling, and JavaScript logic) from a blank canvas. I regularly use fitness calculators to manage my own workouts and muscle growth goals, but I found them visually uninspiring. I wanted to engineer a practical tool that solved my problem, wrapped in a custom, and futuristic UI.

  • 3. How it works:

    • For the user:
      The user inputs their biometric data (age, height, weight), and current physical activity level. The interface features a customer toggle, allowing users to seamlessly switch between metric and imperial units. Upon calculation, the calculator outputs three distinct calorie targets based on the user’s goals, accompanied by a dynamic, CSS generated pie chart visualizing the exact macronutrient split.

    • Technical:
      1. DOM Interactions: The JavaScript uses document.getElementById to actively listen to the HTML input fields and grab the user’s raw data (age, weight, height) when they hit the calculate button.
      2. Data Conversion: Before doing any math, the JavaScript runs conditional (if/else statements). If the user selected imperial units, the code intercepts the data and mathematically converts kilograms to pounds, and centimeters to feet/inches.
      3. The Algorithm: The core engine runs the data through the Mifflin-St Jeor equation (the industry standard for calculating Basal Metabolic Rate), and then multiplies it by a specific activity multiplier.
      4. Dynamic Rendering: Finally, the JavaScript calculates the exact protein, fat, and carb macros, and injects those final numbers back into the HTML table on the screen.

  • 4. Technical Challenges:

    1. Unit Conversion:

if(unitHeight === "cm"){

} else {
const feet = parseFloat(document.getElementById("feet").value);
const inches = parseFloat(document.getElementById("inches").value);
const safeInches = isNaN(inches) ? 0 : inches;
// Mathematical conversion to CM
height = (feet * 30.48) + (safeInches * 2.54);
}
      To maintain the precision of the Mifflin-St Jeor equation, I implemented a Data Normalization layer. This logic handles the complexity of a dual-unit system by intercepting Imperial inputs (lbs, ft, in) and mathematically translating them into Metric units (kg, cm). By converting separate 'feet' and 'inches' fields into a single 'centimeter' value using constants (1 ft = 30.48 cm and 1 in = 2.54 cm), I ensured the core algorithm received consistent, high-precision data regardless of the user's regional preference
    2. CSS Pie Chart: 
      
// Calculating the degree "points" for the CSS gradient
const point1 = proteinPercent;
const point2 = proteinPercent + carbsPercent;

const pieChart = document.getElementById('pie-chart');
pieChart.style.background = `conic-gradient(
    #ff0055 0% ${point1}%, 
    #00f3ff ${point1}% ${point2}%, 
    #00ff88 ${point2}% 100%
)`;
      Instead of taking the easy route and importing a pre-built charting library, I built the macro pie chart using pure CSS. I had to use conic-gradient to create the slices, and apply a mask to cut out the center, so it looked like a ring. The challenge was ensuring the segments aligned perfectly: I implemented an accumulative percentage logic where each segment starts exactly where the previous one ends (e.g., point2 is the sum of Protein + Carbs).
    3. Complex Layouts & Responsiveness: Getting the calculator to look like a floating sci-fi terminal required advanced CSS. I used clip-path:polygon() to cut off the corners from the main container, and I had to master Flexbox to ensure that things stacked on top of each other, especially when fixing the layout for a phone screen.

  • 5. What I learned:

    1. The Bridge Between Languages: I learned that HTML is the skeleton, CSS is the paint, and JavaScript is the muscle. I learned how to use JS to reach into the HTML DOM, pull data, manipulate it, push new data back to the screen.
    2. The Box Model & Positioning:I learned how CSS sizing actually works. I mastered the difference between margin (pushing things away) and padding (invisible forcefields inside the box), and how box-sizing: border-box keeps layouts from exploding.
    3. Problem Decomposition: I learned that I can’t just sit down and “code a calculator”. I have to break the massive problem down into microscopic steps: build the UI, grab the inputs, convert the units, do the math, calculate the macros, build the chart.
